# Revision local de VendeFacil

Fecha: 12 de octubre de 2026, America/Lima.

## Alcance

Revision del checkout local, sin publicar cambios en GitHub o InfinityFree. Se conservaron los datos locales y el diseno aprobado. Las pruebas de cambios de datos usan SQLite en memoria y cuentas ficticias; las comprobaciones HTTP publicas usan el servidor local y su base MySQL.

## Correcciones

- Validacion de filtros publicos y administrativos: arrays, parametros de paginacion invalidos y busquedas demasiado largas ya no provocan errores 500.
- La busqueda administrativa acepta `0` como termino real.
- Telefonos malformados se validan antes de normalizarlos; identificadores no numericos de favoritos devuelven 404.
- Referencias de visitas y agentes de navegador se limitan al tamano aceptado por la base de datos.
- Sitemap compatible con SQLite y MySQL: incluye categorias con productos disponibles, ciudades y tiendas activas. Si falla su generacion, devuelve 503 y registra la incidencia en lugar de ocultarla con un sitemap incompleto.
- Robots excluye las nuevas secciones privadas.
- El mapa incrustado utiliza la ubicacion explicita de Google Maps cuando contiene una consulta o coordenadas. Los enlaces antiguos con esquemas inseguros no se muestran como enlaces de tienda.
- Galerias compartidas usan una rutina de almacenamiento que limpia cargas parciales. Si falla una actualizacion, se conservan las fotos anteriores y se retiran las nuevas.
- Al eliminar un producto o tienda, los archivos se retiran despues de eliminar correctamente el registro. Al eliminar una cuenta, se limpian sus archivos, comprobantes y notificaciones.
- Los reintentos de una transaccion de comprobantes reutilizan el archivo ya guardado.
- El menu del panel utiliza su version compacta hasta el ancho adecuado, evitando desbordamientos en tabletas. El formulario de pago respeta el ancho de moviles pequenos.

## Verificacion

- 63 pruebas aprobadas, con 348 aserciones, sobre autenticacion, contrasenas, perfiles, permisos, productos, planes, pagos, denuncias, favoritos, notificaciones, mapas, sitemap y archivos.
- Las pruebas tambien inyectan fallos deliberados de guardado y borrado para comprobar que los datos y archivos anteriores se conservan.
- 22 pantallas y estados revisados con HTML renderizado por Laravel y los assets reales, en anchos de 1365, 1024, 768, 390 y 320 px. Se volvieron a revisar los tres estados del plan despues de corregir el desbordamiento.
- Selector de ciudad, delivery, busqueda y menu compacto comprobados con Playwright; no se detectaron errores de JavaScript.
- Build Vite y compilacion de vistas correctos; sintaxis PHP revisada.
- Migraciones locales aplicadas y base MySQL accesible.
- Inicio, acceso, registro, recuperacion, sitemap, robots, favicon y las cuatro URLs del sitemap respondieron correctamente por HTTP local. Una busqueda malformada devuelve 422 al pedir JSON.
- Auditoria Composer sin avisos de vulnerabilidades. Auditoria npm de produccion sin vulnerabilidades.

## Limites pendientes

- El correo local usa `MAIL_MAILER=log`; no hay credenciales SMTP. La logica de recuperacion esta probada con un transporte de pruebas, pero no se verifico entrega a una bandeja de correo real.
- npm conserva siete avisos en la cadena de desarrollo de Tailwind 3. La version publicada de `braces` sigue siendo 3.0.3, afectada por el aviso; la solucion propuesta por npm implica cambiar a Tailwind 4. Esa migracion requiere una revision visual separada para conservar el diseno.
- Las capturas de mapas no validan el servicio externo de Google; se verificaron los enlaces y coordenadas generados.
- No se realizaron pagos bancarios: la aprobacion de Yape/BCP sigue siendo manual.
- No se verifico ni actualizo el hosting. Antes de publicar hay que completar la configuracion de produccion, conectar SMTP y cambiar las credenciales expuestas, siguiendo `docs/LANZAMIENTO.md`.
- En el entorno restringido de herramientas de Windows, PHPUnit no puede comprobar la legibilidad del bootstrap aun cuando PHP puede leerlo. La suite se ejecuto con `--no-configuration --do-not-cache-result`, reproduciendo las variables de `phpunit.xml` y usando SQLite en memoria. No se modificaron archivos de `vendor`.
